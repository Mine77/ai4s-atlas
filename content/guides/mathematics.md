把奇数从 1 开始相加，前三步得到 1、4、9，第四步得到 16。看起来，前 n 个正奇数之和总是 n 的平方。数学家要找出这个规律为何对每个 n 都成立；验证软件的工程师则会追问，程序用什么类型保存 n、加法何时溢出、机器算出的结果什么时候仍然对应这个定理。这两类问题都能写成数学命题，但观察证据、证明对象和验收条件各不相同。

## 一条猜想怎样变成能检查的证明

1. **发现规律。** 把 1、3、5 个点依次排成直角形的边框，每多一层，恰好填出一个更大的正方形。进一步算几十项可以帮人排除录入错误或寻找反例。
2. **写清命题。** 输入 n 取所有非负整数，总和从第一个正奇数开始，n 为零时空和等于零。若误写成“前 n 个正整数之和”，连 n 等于 2 就不对。形式化的第一道关是检查这些词有没有被正确翻译。
3. **构造证明。** 零项时两边都为零。假设前 n 项为 n 的平方，下一项是 2n + 1。两者相加恰好等于 (n + 1) 的平方。起点与递推步都有依据，数学归纳法把结论推广到所有非负整数。
4. **交给验证器。** 在 Lean 这类证明助手中，先写自然数、有限和与等号的定义，再为基础情形和归纳步骤提交证明。自动策略能处理代数恒等式，内核可逐项检查最终证明。一个写错但碰巧可证的弱命题也可能通过，因此读者仍要对照第二步的原始陈述。[Lean 关于归纳与自然数的教程](https://lean-lang.org/theorem_proving_in_lean4/induction_and_recursion.html)

学术界的长证明也能按相同思路拆分。Liquid Tensor Experiment 团队把 Clausen 和 Scholze 关于液态向量空间的定理拆成一组定义和引理，让不同贡献者分别形式化。公开的证明蓝图给出引理依赖图，能从主定理追到具体 Lean 代码；社区在提出挑战约一年半后宣布完成验证。对于想读懂长证明的人，依赖图还回答了一个现实问题：卡在这一段时，应该先读哪个较小的结论。[团队证明蓝图](https://leanprover-community.github.io/liquid/sect0001.html) · [完成记录](https://leanprover-community.github.io/blog/posts/lte-final/)

## 工业界怎样把“算对了”变成可验收的规格

项目组要验收一个双精度浮点减法例程。“测试数据都通过”很有价值，但要对一个完整区间作保证，得先把真实机器与理想实数之间的差别写下来。Gappa 文档里有一个可以逐项核查的小例子。[Gappa 的浮点减法证明](https://gappa.gitlabpages.inria.fr/gappa/tools.html)

- **输入是哪一种数？** 两个输入 a 与 b 已经是双精度可表示数。例子要求 a 落在 52/16 到 53/16 之间，b 落在 22/16 到 30/16 之间。这同时规定了输入格式和数值范围。
- **要证明哪个步骤？** 对这些输入，数学上的差 a − b 本身也可用双精度精确表示。因此这一次减法的结果无需再因舍入而改变。若 a、b 来自对传感器读数的舍入，读数转成双精度时引入的误差仍然存在。
- **发现一个精确样例够吗？** 3.25 减 1.5 等于 1.75，两边都能精确表示。这次手算可用来检查自己有没有读错规格。Gappa 的证明处理的是全部符合区间和格式的输入，还能经 Coq 检查。日后若修改输入范围，应对新的命题重新求证。[官方示例与完整假设](https://gappa.gitlabpages.inria.fr/gappa/tools.html)

工业里的真实规模大得多。AMD-K7 处理器的研究将浮点乘法、除法和平方根算法及其满足的 IEEE 规格编码为 ACL2 里的定义和定理，并用证明器验证每一步。项目要同时有人理解运算指令、数值标准和证明系统。对照这一工作，就容易理解为什么数学竞赛的一份正确解答和一款处理器的交付要用不同的验收材料。[AMD-K7 原始论文](https://www.russinoff.com/papers/k7-div-sqrt.pdf)

## 怎么读“自动证明成功率”

- **先找分母。** 从一批题中挑出已经人工形式化的一组再报成功率，衡量的是这一组的证明搜索能力。若产品承诺接收用户的自然语言问题，还要把翻译失败、陈述错误和超时计入端到端表现。
- **记录搜索预算。** 一次生成直接命中、反复尝试后命中，都可以产出同一份正确的最终证明。采购算力和安排交期时，需要每题允许的尝试数、总计算时间以及人工补充的引理。
- **审查假设。** 核对输入范围、使用的公理和依赖，确认没有用占位符跳过待证命题。读工业结果时，还应把证明的模型和实际部署版本一一对应。
- **区分问题的价值与答案的正确性。** 一份通过内核的证明能支撑已写下的命题。它是否回答数学家的原问题、是否覆盖工程师真正担心的误差，仍取决于人怎样定义任务。科学计算中也有类似分工：证明数值程序在给定前提下正确，然后再用实验判断模型是否适合现实材料。[科学计算与研发平台](/guides/scientific-computing/)
